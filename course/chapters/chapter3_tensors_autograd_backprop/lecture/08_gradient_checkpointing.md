# 8 · Gradient checkpointing: recompute instead of store, and what it costs

*Lecture 3, part 8 of 8 · ~20 min reading*

Part 7 left you with a peak that is linear in `L`, linear in `b·s`, quadratic in `s`, and a floor that does not move. When the peak does not fit, there are exactly four levers: a smaller batch (with gradient accumulation to keep the effective batch), a shorter sequence, fewer bytes per activation (mixed precision, fused kernels), or *not keeping the activations at all*. The fourth is this part. It is the oldest idea in the lecture — Griewank published it in 1992 — and the one most often applied without understanding what it buys and what it charges.

## 8.1 The idea

Chen, Xu, Zhang & Guestrin (2016), §4.1, in one sentence: "we propose to drop some of the intermediate results, and recover them from an extra forward computation when needed." Part 7 §7.3 said the layer-ℓ input `x_ℓ` must be *available* when the backward pass reaches layer ℓ. It did not say it must be *stored*. If you kept `x_k` for some earlier `k < ℓ`, you can recompute `x_ℓ` by re-running layers `k … ℓ−1` forward at the moment you need it. Memory for the dropped activations is traded for the compute of re-deriving them.

The PyTorch docs describe the runtime behaviour exactly: "Activation checkpointing is a technique that trades compute for memory. By default, tensors computed during the forward pass are kept alive until they are used in gradient computations in the backward pass. To reduce this memory usage, tensors produced in the passed `function` are not kept alive until the backward pass. Instead, any passed tensors in `args` are kept alive, and the unsaved tensors are recomputed by re-invoking `function` in the backward pass as needed for gradient computation." Read the two verbs: the *inputs* to the checkpointed region are kept; everything *inside* it is dropped and recomputed by calling the region again during backward.

The name is a historical accident worth knowing: it has nothing to do with saving a model to disk (Lecture 6's checkpoints). "Activation checkpointing," "gradient checkpointing," "activation recomputation," and "rematerialization" all mean this.

## 8.2 How much memory it saves: the √n argument

Divide an `n`-layer network into `k` segments and keep only the input to each segment. Chen §4.3: "Assume we divide the n network into k segments the memory cost to train this network is given as follows … cost-total = max_{i=1,…,k} cost-of-segment(i) + O(k) = O(n/k) + O(k)". The first term is the activations of *one* segment — the one currently being recomputed and backpropagated — and the second is the `k` segment boundaries you kept. "Setting k = √n, we get the cost of O(2√n)." From `O(n)` to `O(√n)`, and "This algorithm only requires an additional forward pass during training, but reduces the memory cost to be sub-linear." The abstract's headline: "we design an algorithm that costs O(√n) memory to train a n layer network, with only the computational cost of an extra forward pass per mini-batch", and the empirical result: "we can reduce the memory cost of a 1,000-layer deep residual network from 48G to 7G on ImageNet problems."

The idea recurses. Chen §4.4: "we can recursively apply our memory optimization scheme to each sub-graph", with the recursion `g(n) = k + g(n/(k+1))`; "if we set k = 1, we get g(n) = log₂ n." That is Griewank's 1992 result — "Achieving logarithmic growth of temporal and spatial complexity in reverse automatic differentiation" — and its price: "This will require O(log₂ n) cost forward pass cost, so may not be used commonly." The √n scheme with one extra forward pass is the practical point on the curve; the `log n` scheme exists to tell you the curve keeps going.

What frameworks actually do for transformers is a *different point on the same trade*, not the √n scheme: they take every layer as its own segment (`k = L`). Checkpoint each layer's *input* (`2sbh` bytes) and drop the `34sbh + 5as²b` of internals; at the peak you hold `L` layer inputs plus *one* layer's internals under recomputation — `L·2sbh + sbh(34 + 5as/h)` instead of `L·sbh(34 + 5as/h)`. In Chen's cost formula that is the `O(k)` term at `k = L` plus the `O(n/k)` term at one layer; it uses more boundary memory than `k = √L` would but keeps the boundaries at the natural module edges, and for `L = 12` the difference is negligible. For the GPT-2-small budget from part 7 §7.5: the 8.6 GB of activations becomes `12 × 12.6 MB + 717 MB ≈ 0.87 GB`. A tenth. The model states are still 2.0 GB, untouched — checkpointing does nothing for the floor.

## 8.3 What it costs: compute, and a correctness condition

**Compute.** Every checkpointed region is run forward twice. With the whole model checkpointed, that is one extra forward pass per step. Part 7 §7.1 priced a step at `forward + 2·forward = 3` units; adding a forward makes it `4`, a **33 % increase** in FLOPs. The three sources agree within measurement: Chen, §5: "Because of the double forward cost in gradient calculation, the sublinear allocation strategy costs 30% additional runtime compared to the normal strategy." ZeRO §3.2: activation checkpointing reduces activation memory "by approximately the square root of the total activations at the expense of 33% re-computation overhead." Korthikanti §1: "In our training runs, we observe 30−40% execution time overhead when full activation recomputation is used." Hugging Face: "it comes at the cost of slower training speed (~20%)" — lower, because their default checkpoints only some layers. So: **full checkpointing ≈ +33 % compute for ≈ 10× less activation memory.** Whether that is a good trade depends on whether you were memory-bound or compute-bound, which is a question the production drill's measurements answer.

The trade *can* pay for itself, which surprises people: if checkpointing lets you double the micro-batch, the matmuls run at higher arithmetic intensity (more FLOPs per byte moved), and the wall-clock per sample may come out equal or better. That is a hardware argument, not a guarantee, and no source in this chapter measures it — the 33 % is a FLOP count, and the wall-clock effect is exactly the kind of number the production drill teaches you to measure rather than assume.

**Correctness.** Recomputation assumes the forward is a *pure function* of its inputs. The docs' warning: "If the `function` invocation during the backward pass differs from the forward pass, e.g., due to a global variable, the checkpointed version may not be equivalent, potentially causing an error being raised or leading to silently incorrect gradients." The obvious impure op is dropout: the recomputed forward would draw a different mask, the backward would use a mask that never existed in the forward, and the gradient would be wrong with no error. Hence `preserve_rng_state` — "Omit stashing and restoring the RNG state during each checkpoint … Default: `True`" — the checkpoint saves the RNG state at forward time and restores it before recomputing. It costs a little; do not turn it off in a model with dropout. Anything else that reads mutable state inside the region — a counter, a cache, a `self.step += 1` — is the same bug without the safety net.

**Implementation choice.** "There are currently two checkpointing implementations available, determined by the `use_reentrant` parameter. It is recommended that you use `use_reentrant=False`." The old reentrant variant "does not record the autograd graph during the forward pass, as it runs with the forward pass under `torch.no_grad`" — part 4 §4.5's no-grad, used to make the region invisible to autograd — and it has the limitations that follow: it "only supports the `torch.autograd.backward` API for the backward pass without its `inputs` argument", needs "At least one input and output … `requires_grad=True`", and "does not support checkpointed regions with detached tensors from the computational graph." The non-reentrant version records a graph with special saved-tensor hooks so that the recomputation happens lazily, and "stops recomputation as soon as all needed intermediate activations have been recomputed." The docs now insist: "The `use_reentrant` parameter should be passed explicitly." Pass `False`.

## 8.4 Selective recomputation: recompute what is cheap and big

Full checkpointing treats every activation the same. Korthikanti et al.'s contribution is noticing that they are not. Part 7's formula has two kinds of term: `34sbh` from linear layers and non-linearities, and `5as²b` from attention scores. The attention terms are large — at `s = 1024` they were 70 % of the total — and *cheap to recompute*: "These operations generally have large input sizes and thus large activations, however, the number of floating-point operations (FLOPs) per input element is very low." Softmax, dropout and the score matmul are memory-bound ops; the expensive FLOPs are in the `Q, K, V` projections and the MLP, whose activations are the modest `sbh` terms.

So recompute *only* the attention internals and keep everything else. Their Equation 6: with selective recomputation (and their parallelism tricks) the per-layer memory is `sbh(34/t)` — the `5as/h` term is gone entirely — and the compute price collapses: "The recomputation of these activations introduces only 2.7% and 1.6% FLOPs overhead for these two models." From 30–40 % down to under 3 %, for most of the memory win.

This is also what fused attention kernels achieve *without* an explicit checkpoint: `scaled_dot_product_attention` with a FlashAttention backend never materializes the `(b, a, s, s)` score matrix in the forward pass, and recomputes the needed pieces blockwise in the backward. Same trade, moved into the kernel. When you see a fused-attention flag described as a memory optimization, part 7 §7.4 and this paragraph are why.

## 8.5 Choosing the lever

Put the four levers together with what you now know about each:

| Lever | Memory effect | Compute effect | Changes the math? |
|---|---|---|---|
| Smaller micro-batch + gradient accumulation | Activations ∝ `b`: linear saving; floor unchanged | Same FLOPs total; lower arithmetic intensity per step, so often *slower* per sample | No (if BN-free; batch-norm statistics change) |
| Shorter sequence | `34` term linear, `5as²` term quadratic | Fewer tokens per step | Yes — different training distribution |
| 16-bit activations / fused attention | Halves bytes per activation / removes the `s²` term | Usually faster | Numerically, slightly; Lecture 5 |
| Full activation checkpointing (per-layer segments) | Keeps `L` layer inputs + one layer's internals: ~10× fewer activation bytes at GPT-2 scale; floor unchanged | +≈33 % FLOPs | No |
| Selective recomputation (attention only) | Removes the `5as²b` term | +≈2–3 % FLOPs | No |

Order of operations when a run OOMs, in the order the course recommends: first check for the accumulating-history trap (part 4 §4.6) and `eval()` without `no_grad()` (part 4 §4.5) — those are bugs, not budgets; second, confirm the arithmetic — is the peak where part 7 §7.5 predicts, or is something else holding memory; third, fused attention and 16-bit, which are nearly free; fourth, selective recomputation; fifth, full checkpointing; and last, the smaller micro-batch, because it is the one that costs throughput without a compensating win. Project 2's memory calculator (`memory_math.py`, due end of week 3) encodes exactly this table: given a config and a batch shape, it should produce the floor, the activation slope, and the effect of each lever — and the production drill this week is its first data point.

## 8.6 Why training memory grows with batch × sequence length × depth — the lecture in one paragraph

A tensor is metadata over storage (part 1). A model's forward pass is a chain of local operations on tensors with named axes (parts 2, 5). Autograd records each operation as it runs, saving whatever the local derivative rule will need (parts 4, 6). The rule for a layer's parameter gradient needs that layer's *input*, and the input is only used after every later layer has run backward, so at the end of the forward pass every layer's saved tensors are alive at once (part 7). Each layer saves `sbh(34 + 5as/h)` bytes — every term proportional to tokens `s·b`, one term proportional to `s²` — and there are `L` layers. Hence batch × sequence length × depth, with a quadratic kink in the sequence term. Reverse mode makes the gradient cheap in compute at exactly this price in memory (part 6); checkpointing lets you pay part of the price in compute instead, at 33 % for the full trade or under 3 % if you recompute only the attention scores (part 8). Every OOM you meet for the rest of the course is one of these sentences.
